# Пример нормализации:

for subj in data.get("subjects", []):

                     if name in current_classes}

3.5. OR-Tools CP-SAT — краткое описание

В проекте используется CP-SAT — решатель из библиотеки OR-Tools от Google.

Что такое CP-SAT

CP-SAT (Constraint Programming + SAT) — это решатель для задач целочисленного программирования, основанный на SAT-подходе и технике Lazy Clause Generation [citation:13].

Он сочетает:

  • Constraint Programming — ограничения описываются напрямую;
  • SAT-решатель — эффективный поиск с CDCL (Conflict-Driven Clause Learning) [citation:16];
  • Simplex — линейная релаксация для ускорения.

Ключевые возможности

ВозможностьЧто даёт
Целочисленные переменныеВсе значения — int64, без ошибок округления [citation:11]
Булевы переменныеИдеально для расписаний: x[day][slot] = 0 или 1
Линейные ограничения2x + 3y ≤ 10, sum(...) == 1
Глобальные ограниченияAllDifferent, Element, AddAllowedAssignments [citation:9]
МногоядерностьРаботает на нескольких ядрах параллельно [citation:13]
Ограничение времениmax_time_in_seconds = 30 — не зависнет

Статусы решения

СтатусЧто значит
OPTIMALНайдено оптимальное решение
FEASIBLEРешение найдено, но не доказано, что оно оптимальное
INFEASIBLEДоказано, что решения не существует
UNKNOWNНе найдено за отведённое время [citation:17]

Применение в проекте

В scheduler.py CP-SAT используется для решения задачи составления расписания — это классическая задача Constraint Satisfaction Problem (CSP).

# Создание модели
model = cp_model.CpModel()

# Переменные: x[i][d][s] = 1, если урок i стоит в день d, слот s
x[(i, d, s)] = model.NewBoolVar(f"x_{i}_{d}_{s}")

# Ограничение: каждый урок — ровно в одном слоте
model.Add(sum(x[(i, d, s)] for d in range(DAYS) for s in range(SLOTS_PER_DAY)) == 1)

# Ограничение: у класса не может быть два урока одновременно
model.Add(sum(x[(i, d, s)] for i in lessons_here) <= 1)

# Решение
solver = cp_model.CpSolver()
status = solver.Solve(model)
Почему CP-SAT: наивный перебор (backtracking) для школы с 7+ классами может занять часы. CP-SAT решает ту же задачу за секунды благодаря умному отсечению и обучению на конфликтах [citation:16].

4. Модуль scheduler.py

4.1. Назначение

Это сердце программы — решатель расписания на базе OR-Tools CP-SAT.

Зависимости: models.py, ortools.sat.python.cp_model.

4.2. Константы

КонстантаЗначениеЧто значит
DAYS5Количество учебных дней (Пн–Пт)
SLOTS_PER_DAY7Количество уроков в день
MAX_SLOTS35Всего слотов в неделю (5 × 7)

4.3. Класс Scheduler

class Scheduler: def __init__(self, teachers, classes, subjects, rooms):

Что делает: принимает списки объектов из models.py и сохраняет их в словари по id для быстрого поиска.

self.teachers = {t.id: t for t in teachers}
self.classes  = {c.name: c for c in classes}
self.subjects = {s.name: s for s in subjects}
self.rooms    = {r.id: r for r in rooms}

Зачем словари: поиск по ключу — O(1) вместо O(n) в списке. Для больших школ это важно.

4.4. Метод _precheck() — предварительные проверки

def _precheck(self) -> str:

Что делает: быстрая проверка — возможно ли вообще составить расписание. До запуска OR-Tools.

Возвращает: строку с ошибкой (если проблема) или пустую строку (всё ок).

Что проверяет:

№ПроверкаЧто ловит
1Сумма часов класса ≤ 35Перегруз класса
2У каждого предмета есть учительПредмет без преподавателя
3Нагрузка учителя ≤ 35 слотовПерегруз учителя
4Есть хотя бы один кабинетОтсутствие кабинетов
Зачем: OR-Tools может «зависнуть» на нерешаемой задаче. Проверки отсекают заведомо невозможные случаи за миллисекунды.

4.5. Метод _find_teacher() — поиск учителя по предмету

def _find_teacher(self, subject: str) -> Teacher:

Что делает: проходит по всем учителям и возвращает первого, у которого subject в списке subjects.

Возвращает: объект Teacher или None, если никто не ведёт предмет.

4.6. Метод _find_rooms_for() — подбор кабинетов

def _find_rooms_for(self, subject: str, class_name: str) -> List[int]:

Что делает: возвращает список подходящих кабинетов для урока.

Логика:

  1. Отсеивает кабинеты, где capacity < students.
  2. Сначала добавляет специализированные (например, «Физика» для физики).
  3. Потом — обычные.
Почему сначала спец.: чтобы OR-Tools предпочёл поставить физику в кабинет физики. Если он занят — используется обычный.

4.7. Метод solve() — главный метод

def solve(self) -> tuple[bool, str]:

Что делает: составляет расписание через OR-Tools CP-SAT.

Возвращает: (True, "OK") при успехе или (False, "сообщение") при ошибке.

Пошагово:

Шаг 1. Проверки

err = self._precheck()
if err:
    return False, err

Шаг 2. Импорт OR-Tools

from ortools.sat.python import cp_model
model = cp_model.CpModel()

Шаг 3. Создание списка уроков

Проходит по всем классам и предметам, создаёт отдельный урок для каждого часа:

lesson_specs = []
for cls in self.classes.values():
    for s in self.subjects.values():
        hours = s.hours_per_week.get(cls.name, 0)
        for _ in range(hours):
            lesson_specs.append((cls.name, s.name, teacher.id))

Итого: lesson_specs — плоский список всех уроков, которые надо расставить.

Шаг 4. Переменные модели

Для каждого урока создаётся 5 × 7 = 35 булевых переменных:

x[(i, d, s)] = model.NewBoolVar(f"x_{i}_{d}_{s}")

x[(i, d, s)] == 1, если урок i стоит в день d в слот s.

Шаг 5. Ограничения

ОграничениеЧто гарантирует
sum(x[i][*][*]) == 1 Каждый урок стоит ровно в одном слоте
Для класса/дня/слота: sum ≤ 1 У класса не может быть два урока одновременно
Для учителя/дня/слота: sum ≤ 1 Учитель не может вести два урока одновременно
Для кабинета/дня/слота: sum ≤ 1 В кабинете не могут идти два урока
Запрещённые слоты: x == 0 Учитель не ведёт урок в запрещённое время

Шаг 6. Решение

solver = cp_model.CpSolver()
solver.parameters.max_time_in_seconds = 30.0
status = solver.Solve(model)

Лимит времени — 30 секунд: чтобы не зависнуть на сложной задаче.

Шаг 7. Извлечение расписания

for i in range(n):
    for d in range(DAYS):
        for s in range(SLOTS_PER_DAY):
            if solver.Value(x[(i, d, s)]) == 1:
                self.schedule.append(Lesson(d, s, ...))

Проходит по всем переменным и собирает те, где значение 1.

⚠️ Почему OR-Tools, а не backtracking: наивный перебор для 7 классов может занять часы. OR-Tools с CP-SAT решает ту же задачу за секунды благодаря умному отсечению вариантов.

6.4. Функция _generate_key_from_number(n)

def _generate_key_from_number(n: int) -> str:

Что делает: превращает число n в ключ формата SP-XXXX-XXXX-XXXX.

Алгоритм:

raw = f"{SECRET_SALT}-{n}"           # "SchoolPlanner_2026_SecretKey_v1-1"
h = hashlib.md5(raw.encode()).hexdigest().upper()   # 32 hex-символа
return f"SP-{h[0:4]}-{h[4:8]}-{h[8:12]}"

Свойства:

  • Детерминирован — для одного n всегда один ключ.
  • Необратим — по ключу нельзя восстановить n без соли.
  • Уникален — разные n дают разные ключи.

6.5. Функция is_valid_key(key)

def is_valid_key(key: str) -> bool:

Что делает: проверяет, валидный ли ключ.

Алгоритм:

  1. Проверяет формат (начинается с SP-).
  2. Перебирает n от 1 до 100 000.
  3. Для каждого n генерирует ключ и сравнивает.
  4. Если совпало — True.
Почему перебор: мы не храним список валидных ключей. Каждый ключ проверяется на лету — по формуле. Это безопаснее.

6.6. Функция load_license()

Возвращает: {"activated": True/False, "key": "SP-..."}

9.2. Поток данных при составлении расписания

  1. Пользователь нажимает «Составить расписание».
  2. desktop_app.build_schedule() вызывает advisor.analyze(data).
  3. Если есть ошибки — выводятся пользователю, стоп.
  4. Конвертирует dict → объекты (Teacher, SchoolClass, Subject, Room).
  5. Создаёт Scheduler(...) и вызывает solve().
  6. Scheduler.solve() строит модель CP-SAT и решает.
  7. Возвращает список Lesson.
  8. desktop_app отображает расписание.
  9. Пользователь может перемещать уроки (клик-клик).
  10. При экспорте — excel_export.export_to_excel() создаёт .xlsx.

9.3. Поток данных при активации

  1. При запуске desktop_app.main() вызывает license.is_activated().
  2. license.load_license() читает license.json из APPDATA/LOCALAPPDATA.
  3. Если ключ есть и валиден — полная версия.
  4. Если нет — демо-версия с баннером.
  5. Пользователь нажимает «🔑 Ввести ключ».
  6. license.is_valid_key() проверяет ключ (перебор до 100000).
  7. license.save_license() сохраняет ключ в оба пути.

10. Ключевые технические решения

10.1. Почему OR-Tools, а не backtracking

10.2. Почему JSON, а не база данных

  • Простота — один файл, легко править вручную.
  • Портативность — легко передать другому.
  • Нет зависимостей — не нужен SQLite/PostgreSQL.
  • Для школы — объём данных маленький (сотни записей).

10.3. Почему офлайн-проверка ключа

  • Нет сервера — не надо платить.
  • Работает без интернета.
  • Быстро — проверка за миллисекунды.
  • Минус: ключ можно вычислить, если знать соль.

10.4. Почему Flet, а не Tkinter

КритерийTkinterFlet
Внешний видустаревшийсовременный
КроссплатформенностьWindows/Linux/Mac+ Android/iOS/Web
Сложность вёрсткивысокаянизкая
Размер .exe~20 МБ~150 МБ
Компромисс: Flet даёт красивый UI и кроссплатформенность, но .exe больше из-за встроенного движка Flutter.
